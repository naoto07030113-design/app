# UI/UXの制作ルール

## 順序
1. 利用者と操作の流れ
2. 画面の階層と一覧
3. 参考画像・既存デザインの固定項目
4. PC/スマホ別のワイヤー
5. UIモック・画面レビュー
6. ユーザー確定
7. コード実装・DB・外部連携

ユーザー指定の画面・参考サイトは、構図、余白、文字、階層、サイズ、位置、カラー、画像・アイコン、角丸、影、モーションまでトレース。レイアウト変更を提案する時は別案として示す。元デザインを勝手に変更しない。

## 共通デザイン基準（新規UI・改修時の初期値）

以下はアプリ、Webサイト、業務システムの共通デザイン原則。画一的な配色・見た目を強制するものではなく、既にユーザーが確定したデザイン、案件固有のブランドガイド、業務上の可読性・アクセシビリティを優先する。

### 1. 配色：70 / 20 / 10
- **ベース 約70%**：背景・余白・大きな面を構成するニュートラルカラー。
- **メイン 約20%**：ブランド色・主要UI・見出し領域など、情報構造を作る色。
- **アクセント 約10%**：CTA、選択状態、重要な注目要素などに用いる色。
- 面積比は視覚的な目安であり、ピクセル単位の厳格な割合ではない。エラー・警告・成功などの状態色は意味とコントラストを優先して別途設定する。
- テキストと背景のコントラストは原則 WCAG AA（通常テキスト4.5:1以上、大きな文字3:1以上）を満たす。色だけで状態や重要度を伝えない。
- ブランドごとに具体的なカラートークンを設定し、全案件へ同一の色を強制しない。

### 2. 書体：原則2ファミリー以内
- 見出しと本文を含め、UI全体で使用する書体ファミリーは原則2つ以内。可能であれば1ファミリーのウェイト差を優先する。
- 日本語・英数字のフォールバックは同じ書体グループとして扱う。既存ブランド指定フォント、専門的な数値表示、アイコンフォント等は必要に応じて例外とする。
- 文字サイズ、太さ、行間、字間はデザイントークンで統一する。小さすぎる文字や、装飾的な英字見出しの多用を避ける。

### 3. 余白：8pxグリッド
- margin、padding、gap、セクション間隔、コンポーネントの配置は原則8pxの倍数（8 / 16 / 24 / 32 / 40 / 48 ...）で設計する。
- 密度の高い業務UIや細かな調整には4px単位を補助的に使ってよい。枠線1px、アイコン位置、文字ベースライン等は機械的に8pxへ丸めない。
- PC・スマホごとに余白トークンを定義し、タップ領域やアクセシビリティを優先する。

### 運用・確認
- UI_SPECと画面モックに「色の役割とトークン」「書体構成」「8px間隔ルール」を記載する。
- 既存画面の改修では現在のデザインをまず確認し、明示指示がない限り全面的に塗り替えない。
- レビュー時に配色・タイポグラフィ・間隔の一貫性をチェックする。例外は理由とともにUI_SPECに記録する。

## 品質とトーン
- 日本語にはヒラギノ角ゴ、游ゴシック、Noto Sans JP等を用途で選ぶ。本文400前後、小見出し500〜600、主見出し600前後を基本にし、極端な太字を乱用しない。
- 本文字間は0〜0.02em、行間1.7〜1.9、見出しは適度な字間と1.25〜1.45を目安。大きすぎる英字飾り見出しや規則的すぎるカード配置を避ける。
- PCダッシュボードは簡素に要点を集約、各タブで情報を詳しく表示する。
- スマホ画面は縦長に詰めず、必要なタブやナビゲーションで分割する。
- 空状態、読み込み、検証エラー、ネットワーク失敗、権限差、フォーカス、キーボード操作を設計する。
- 事業・ブランドで色と世界観を選ぶ。全製品を同じAI風デザインで統一しない。
- 制作物に絵文字を使わない。

## UI_SPECの各画面に必要な事項
画面名、目的、PCレイアウト、スマホレイアウト、表示情報、主操作、遷移、権限、空状態、エラー状態、参考画面の再現ポイント、受入条件。
