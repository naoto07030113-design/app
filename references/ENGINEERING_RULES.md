# 実装と運用の基本設計

- 既存資産のコード・DB・権限・テスト・仕様を確認してから再利用する。READMEだけで安全性や本番対応を保証しない。
- 新規Web案件の標準候補は Next.js / TypeScript / Tailwind CSS / Supabase / Vercel。ただし既存技術や単一HTML、ネイティブアプリの方が適切なら優先。
- 実装前にUIモックを確定。UIを無断変更するためのフレームワーク都合は許容しない。
- 施設・部署・役割・ユーザーごとのアクセス制御をサーバー側/DB側で設計。フロントの表示切替だけに頼らない。
- 医療・介護・採用・給与・会計の情報は機微性を判定し、データ最小化、漏洩防止、保存期間、アクセス監査を扱う。
- ユーザーの同意なしで本番データ投入・送信・削除・公開・給与確定などの操作はしない。
- 操作履歴、承認履歴、エラー監視、バックアップ、復元テスト、例外処理、再試行と冪等性の要否を決める。
- コネクタ/API/MCP/Browser Useの存在、権限、利用規約、費用を確認し、未検証連携は「候補」とする。APIなしでも行える範囲を分ける。
- AIエージェントのツール実行はリスク分類・実行前検証・人的承認・実行結果検証・事故時の補償を検討。外部副作用の完全なロールバックを保証しない。
- ビルド、lint、型検査、単体テスト、主要フローE2E、レスポンシブ確認を対象技術に沿って定義。走らせていないテストを合格としない。
- 秘密鍵や個人情報をGitHubの公開リポジトリへ保存しない。
