# 主要な案件の型

型を1つ選び、必要なものだけ混合する。

| 型 | 初期画面 | MVPで必須の検討 |
| --- | --- | --- |
| 介護/福祉/医療の管理 | 要点だけのトップ、患者・利用者、施設、記録、予定、設定 | 施設別権限、機微データ、操作履歴、現場入力 |
| 予約・CRM | カレンダー、顧客、メニュー、シフト、予約変更、通知 | 競合予約、15分刻み等のルール、権限、通知失敗 |
| クリニック/企業HP | FV、サービス、特徴、詳細、事例、問い合わせ | ブランド忠実性、スマホ導線、SEO、コンテンツ正確性 |
| 採用・求人 | 求人、応募者パイプライン、面接、会話、権限 | 部署ごとの閲覧境界、同意、個人情報、通知 |
| 経理/給与 | 収集、照合、要承認、反映、証憑、履歴 | 既存会計システム優先、誤反映防止、手動承認 |
| AIワークフロー | タスクキュー、実行状況、承認、失敗、ログ | 入力検証→計画→承認→実行→検証→報告 |
| 消費者向けアプリ | ホーム、機能、履歴、プロフィール、設定 | 端末、継続体験、UIの世界観、課金有無 |
| AIエージェント基盤 | Tool Call、ポリシー、承認、履歴、復旧 | 実行前後の記録、再実行・補償、保証範囲 |
| 単一画面試作 | 1〜2画面、架空データ、操作可能なUI | 実運用不可の部分を明示、最短の確認方法 |

どの型でもモバイル／PCの要否を検討し、不要な管理機能をむやみに増やさない。
