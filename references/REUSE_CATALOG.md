# 既存成果物の再利用ルール

## GitHubで内容を確認した再利用候補
- HP: Next.js / TypeScript / Tailwind / Supabase の治療院向け予約・患者・会計管理。UI・DB設計の参考。ただし権限や個人情報の保護は再検証する。
- yoyaku: 予約CRM、カレンダー、シフト、顧客導線。localStorage版と本番DB版を区別する。
- stretch-ito: 静的な医療・治療院向けサイト。情報設計、レスポンシブ、FAQ、予約導線の参考。
- HP-: 映像主体の静的LP。スクロール連動演出の参考。動画素材の権利を確認する。

## その他の再利用候補
- 共同生活援助: 複数棟、部屋カード、日報、シフト。部屋数は棟別に管理。
- 採用: 福祉・療術の応募者、求人、会話と管理権限を分離。
- 経理: 既存会計ソフトと重複させず、収集・照合・承認・反映・監査を設計。
- 医療系HP: 既に固定されたビジュアルやスクロール動線を尊重する。
- AIエージェント基盤: 操作前検証、操作履歴、人的承認、補償処理。
- AIワークフロー: タスクキュー、実行状態、失敗時対応、ログと報告。

## 利用時の確認
1. 実際の対象リポジトリとブランチの最新版を読む。
2. 再利用可能なコード、参考UI、未実装のアイデアに分ける。
3. ユーザーが後から修正・確定した内容を優先。
4. 秘密情報や非公開資産をこの公開リポジトリに複製しない。
5. 権限・ライセンス・テスト・外部連携は再検証する。

ここに載ることは動作保証や実装済みの証明ではない。
