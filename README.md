# ITO Project Factory

**「〇〇を作りたい」だけで、大枠の設計を作るための共通スキル集。**

目的は、毎回ゼロから仕様を説明する手間を減らし、過去の決定事項・設計パターン・実装資産を再利用することです。現段階で再利用するのは「設計ルール」と「確認済み資産への参照」です。既存製品のコードや内部情報は勝手に複製しません。

## 使い方

Codexでこのリポジトリを開いて、例えば次のように送ります。

> グループホーム管理システムを作りたい。ITO Project Factoryを使って大枠を作って。

> 新しいクリニックHPを作りたい。UIを先に決める形で設計して。

> 社内の経理自動化を作りたい。既存システムを確認して、最小構成から設計して。

実行すると、依頼内容に合わせて **projects/〈案件名〉/** 内へ以下7点を作成する規則です。

1. `PROJECT_BRIEF.md`：目的・顧客・MVP・優先順位
2. `UI_SPEC.md`：画面一覧・PC/スマホ構成・遷移・デザイン
3. `ARCHITECTURE.md`：使用技術・サービス構成・認証・外部連携
4. `DATA_MODEL.md`：データ・権限・履歴（不要なら理由を記載）
5. `TASKS.md`：実装順序・検証条件・担当
6. `PROJECT_STATE.md`：確定事項・仮定・保留・現在地
7. `CODEX_HANDOFF.md`：Codexにそのまま渡せる実装指示

空のひな形ではなく、**案件固有の中身を埋めます**。「大枠を作って」では設計まで。「実装して」ではUI確定後、実装に進みます。

## ディレクトリ構成

- `AGENTS.md`：Codex等が最初に読む全体ルール
- `.agents/skills/ito-project-factory/SKILL.md`：Codex用スキル
- `.claude/skills/ito-project-factory/SKILL.md`：Claude Code用スキル
- `references/`：プロジェクト種別・既存資産・UI・実装方針
- `templates/OUTPUT_CONTRACT.md`：7点の作成要件
- `examples/STARTER_PROMPTS.md`：最短の指示例

## 設計上の重要ルール

- **UI/UX確定 → 機能・DB実装**の順番。画像・参考サイトの指定があれば勝手に変えない。
- 前に出した修正指示や固定仕様を、初期提案より優先する。
- PCダッシュボードは簡潔にし、詳細はタブへ。スマホは見やすいタブ分割。
- GitHubを仕様とコードの正本、Notionを業務の進捗・タスク管理に分担する。
- 権限、操作履歴、バックアップ、障害監視、承認フローを必要に応じて設計する。
- 制作物に絵文字を使わない。

## 適用範囲と制約

本リポジトリを開いたCodex/Claude Codeには `AGENTS.md` とスキルを適用できます。ただし**GitHubに保存するだけで全チャット・全リポジトリへ自動導入されるものではありません。** 他のリポジトリへ適用する場合は、スキルおよび参照文書をコピーするかCodexに明示して読み込ませてください。

このリポジトリは公開設定です。個人情報、利用者記録、給与、社内機密、APIキー、未公開コード・仕様を追加しないでください。

「設計書を生成できる」と「システムが実装・公開済み」は別です。作成・検証・連携の実施状況は明確に区別します。
